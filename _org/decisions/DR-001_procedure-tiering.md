# DR-001 手続きの格付け（軽手続き／正式手続き）

- 種別: 決定記録（Decision Record）
- 状態: **承認済み**
- 承認者: CEO
- 承認日: 2026-11-04
- 出所: Muse 提案「改善3点」の第3項（趣旨: 仕組みの重さを中身に釣り合わせる）
- 記録作成: Fable 5（2026-11-03、Muse からの依頼による落とし込み）
- 適用開始: 本記録の承認日以降に起票される新規案件から

---

## 1. 決定事項

案件を **軽手続き** と **正式手続き** の2区分に分け、区分に応じて手続きの重さを変える。

### 1.1 軽手続き

**起票 = 実施可。宿題1枚で成立し、WO（作業指示書）は起こさない。**

次の **すべて** に当てはまる案件が対象:

| # | 条件 |
|---|---|
| A | 取り返しがつく（元に戻せる、または影響が一時的） |
| B | 本番ノード（不夜城／UT2）の権限・鍵・設定を変えない |
| C | お金が動かない |
| D | 外部への送信・公開を伴わない |

- 形式: 宿題の最小形（**目的・完了条件・期限** の3行）のみ。
- 完了: 「済み」＋証拠1点。
- 報告: 事後でよい。

### 1.2 正式手続き

**現行どおり: WO 起案 → CEO 承認 → 実施 → 受け入れ確認。**

次の **いずれか** に当てはまる案件が対象:

| # | 条件 |
|---|---|
| 1 | 本番ノードの権限・鍵・アカウントの変更（例: WO-MUSE-001） |
| 2 | 不可逆な操作（削除、契約、プラン切替など元に戻せないもの） |
| 3 | お金の移動・支払い・解約 |
| 4 | 外部への送信・公開 |

軽手続きの条件 A〜D のいずれか1つでも満たさない案件は、正式手続きに当たる。

---

## 2. 付帯決定

| 項目 | 決定内容 |
|---|---|
| 起票の最小形 | どちらの区分でも、起票は「目的・完了条件・期限」の3点が揃えば成立する。文書の厚さは審査対象にしない。 |
| 区分の判定者 | 起票者が自己判定する。迷ったら重い方（正式手続き）に倒す。判定が割れた場合は CEO が決める。 |
| 既存案件の扱い | 本区分は新規案件から適用する。進行中の案件（WO-MUSE-001 等）の手続きは変えない。 |

---

## 3. 運用上の補足（Muse の参考意見を採録）

- 軽手続きの案件は、Muse の判断待ち一覧にも「軽」として載せる。CEO の判断負荷を増やさない形で運用する。
- **読み取り調査の線引き**: 現状把握だけの読み取りは軽手続き。その結果を受けた設定変更は正式手続き。調査と変更は別案件として起票する。

---

## 4. 判定の手順（起票者向け）

1. 条件 A〜D をすべて満たすか確認する。
2. すべて満たす → 軽手続き。宿題（目的・完了条件・期限）を1枚起票し、そのまま実施する。
3. 1つでも満たさない、または迷う → 正式手続き。WO を起案して CEO 承認を待つ。
4. 判定に異論が出た場合は CEO の判断に従う。
